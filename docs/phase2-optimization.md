# 第二阶段优化使用说明

本轮仅本地代码、迁移、测试和提交。iOS 已无限期搁置，苹果手机用员工网页 `/staff/`。

管理员在「打卡记录」旁的「考勤规则」设置启用状态、上下班时间、宽限、星期和生效日期。迁移默认从执行当天北京时间生效，不会把历史无规则月份判为缺卡。工作日历按 `YYYY-MM-DD,HOLIDAY|WORKDAY,名称` 每行一条粘贴，最多400行；有效行写入，错误行给行号，已有日期覆盖。页面提供格式示例，请以国务院办公厅当年通知为准，系统不预置未经核实的年度节假日。

「月度考勤」选择月份/部门，查看每人汇总和每日明细，下载带BOM的Excel兼容CSV；工作台「考勤异常」可展开明细。员工网页打卡页及Android工作台「我的本月考勤」显示本人异常，点击发起补卡预填日期/类型，仍受原补卡期限和审批约束。当前停用员工因没有停用时间字段整段不纳入，重新启用后按现有事实重算。详细判定与月度口径见 api.md。

考勤规则页下方可调整催办冷却、自动催办启用、阈值与重复间隔。发起人在通用申请、合同、资产详情点击「催办」，冷却中显示下次可用时间。自动任务每10分钟巡检，默认满24小时提醒当前在职审批人一次，改派后重新计时；0表示不重复。不向发起人额外发自动通知。通知统一走消息中心和既有Android FCM链路。

员工填单顶部「从模板填单」可套用请假、出差、外出、报销内容。「保存为常用模板」仅保存理由、类型、半天选项、报销明细与抄送人等内容；每人最多30个。模板管理可重命名或删除。本人详情「复制再发起」不会复制日期、附件、状态或审批记录；请重新选择日期及证明文件。停用的假种/抄送人会过滤，最终仍由服务端完整校验。

网页和Android的JPEG/PNG大图（>1.5MB或长边>2560）自动等比压缩，最长边2560，JPEG质量0.82，必要时降至0.60，透明区域铺白底。体积反增则保留原图，小图和PDF原样上传，压缩后仍超过10MB时拒绝。压缩/上传显示进度，失败可重新选择同名文件；网络写操作通过现有busy保护防重复提交。

导航角标拆分通用审批、合同、资产、任务和未读系统通知，点击数字可进入对应过滤列表；0隐藏，>99显示99+。工作台和消息中心分别显示待审批和任务；「全部待办」保留旧混合入口。登录、导航、写操作、窗口焦点恢复及每60秒刷新，页面隐藏暂停。报销财务待支付单独由payments字段提供。

工作台快捷导出包含本月考勤、本月报销、本月审批、合同台账。报销按提交月份统计，可通过API `basis=approved` 改按最终批准月份；导出含合计行，CSV防公式注入。保留原打卡定位来源、补卡来源和导出字段。

本地验收：先 `source scripts/env.sh`，Flutter补充 `export PATH=/home/box/flutter/bin:$PATH`（若工具已在PATH则不需要），运行 `scripts/dev-up.sh`；随后运行所有现有verify脚本和 `scripts/verify-opt-phase2.py`，再运行 `npm --prefix admin run test:e2e`、Flutter analyze/test。后端HTTP测试使用独立的oa_push_test、oa_review_test和oa_opt_test数据库（与oa同一localhost PostgreSQL实例），需预先存在，可用本地createdb创建；单元测试和HTTP测试结果写在Surefire报告。全部验收精确结果见本次交付的 `.runtime/codex-opt-phase2-last-message.md`，该文件不纳入Git。

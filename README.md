# 公司内部 OA · 一期与二期加班、补卡、日程会议

Java 21 + Spring Boot 3 单体后端，PostgreSQL 保存业务，Redis 保存会话及登录失败计数，本地目录保存证明文件；Vue 3 + Vite + TypeScript 中文管理后台。提供管理员后台、财务报销处理入口和全员消息中心；新增同一套代码面向 Android / iOS 的 Flutter 员工 App，员工可直接提交申请、打卡及处理审批。

## 已实现

- 工号或手机号登录、BCrypt 密码、首次强制改密、改密后全部旧会话失效、退出、停用立即生效。角色：员工、直属上级、部门负责人、管理员、财务/行政。
- 部门树、主部门、直属上级、部门负责人、账号开通/编辑/重置密码/停用；组织循环检查和关联角色检查；保留历史数据。
- 管理员维护 Wi-Fi SSID 和办公网出口 IP，配置假期及年度上限、年假/调休剩余余额、审批分流阈值。
- 请假、出差、外出、报销提交与审批。支持半天，审批链去重、一级/二级分流、通过/驳回、撤回、未开始撤销和站内通知。报销支持后台代提交、费用明细合计校验、必填多张票据、财务审批和人工支付登记，不自动打款。
- 年假、调休最终批准扣余额，撤销返还；事假、病假不扣余额、支持年度上限；法定假须证明。审批链及规则快照，数据库事务和行锁防止重复扣减、并发超扣。
- 正常打卡和出勤 API 均强制定位；正常打卡校验公司网络；出勤校验本人有效出差/外出批准时段。仅记录事实，不计算迟到、早退、缺卡，加班、补卡沿用同一套申请审批，详见下文。
- 管理后台查询审批、打卡，分页与筛选、CSV 导出、证明上传/鉴权下载、站内通知、管理审计；开发环境有模拟打卡页，生产环境不提供模拟接口。

- 公告支持全员/部门及下级、启用员工接收人快照、多附件、已读回执与统计、管理员撤回及审计。申请可抄送在职同事，消息中心汇聚待办、本人发起、抄送、系统通知和公告，提供未读汇总。

## 二期增量：加班与补卡

- 员工 App 的工作台与审批入口新增「补卡」「加班」；后台支持代提交、抄送、审批、筛选、详情和中文 CSV 导出。复用现有会话、审批链、消息中心和审计。
- 补卡选择正常打卡或出勤，填写过去的北京时间与必填原因，无需定位或历史网络。默认最迟在补卡日期后的第 **3** 个自然日提交（包含第3日，后台「审批分流」可改为0–365）。同人同时同类型已有记录、待批或已批补卡时拒绝重复。出勤在提交和最终批准时都核验 `startAt <= 补卡时刻 < endAt` 的有效已批出差/外出；请假不阻止补卡。
- 补卡仅批一次：直属上级 → 未配置则部门负责人 → 均无则有效管理员，禁止自批。待批可撤回，批准按申请时间落一条补卡记录，不能撤销；历史现场打卡保留原样。后台、员工打卡记录和导出可区分来源；不补造定位。
- 加班采用与请假相同的自然日半天模型（09:00/13:00开始，13:00/18:00结束，含周末）；必须有结束时间，允许过去及跨年时段。与待批/已批请假和加班互斥，允许出差/外出期间加班。沿用请假可配置阈值（默认 **1天**），超过阈值才追加部门负责人，按既有规则去重。
- 加班最终批准按 **1:1** 默认比例计入开始年度调休；后台比例可设0.01–100、最多两位小数，提交时快照比例和兑换额度。余额与流水使用十进制、事务和行锁；个人中心刷新可见新余额，后台有「余额流水」。调休余额支持最多四位小数，其余假期保留半天录入规则。
- 加班待批可撤回；已批且未开始可撤销、通知已批人并精确退回兑换额度。若已使用调休导致余额不足则整笔拒绝撤销，先处理已使用额度；已开始不可撤销。不做加班费、调休到期、跨年结转、班次或迟到早退缺卡统计。
- Flyway **V5** 增量扩展，不改写历史打卡或余额，不补造历史流水；新批准/撤销及管理员余额设置均记录流水。

## 方式一：本机运行（本次实际采用）

本机没有 Docker，已使用仓库内 JDK 21.0.13、Maven 3.9.9、PostgreSQL 17.11、Redis 8.0.2 和系统 Node.js 实际启动。以下命令在仓库根目录执行：

```bash
cd /workspace/oa-system
bash scripts/install-local.sh   # 已安装可略过；下载只写入本仓库 .tools
bash scripts/dev-up.sh
```

自动安装脚本适用于 **Debian 13 x86_64**，需要系统已具备 Node.js 22.12+（或 20.19+）、npm、Python 3、curl、tar、dpkg-deb、ripgrep、openssl，以及 Debian 13 常用运行库。当前环境这些基础工具均已存在；脚本提取 PostgreSQL/Redis 的 deb 到 `.tools/system`，不会注册系统服务，也不需要 root。其他系统可先安装上述基础工具和 JDK 21、Maven 3.9、PostgreSQL 17、Redis 7+，再按下文手动启动；不要直接在不兼容发行版使用脚本中的 Debian 二进制。

`dev-up.sh` 初始化数据库、启动 PostgreSQL/Redis，执行后端测试与打包、前端依赖安装/类型检查/构建，然后启动后端和 Vite。重复执行保留数据，并在构建成功后重启后端加载新代码。所有开发服务仅监听回环地址：

| 服务 | 本机地址 |
| --- | --- |
| 管理后台 | http://127.0.0.1:5173 |
| 后端健康检查 | http://127.0.0.1:8080/api/health |
| PostgreSQL | 127.0.0.1:55432，数据库/用户 `oa`，仅开发密码 `oa-local-only` |
| Redis | 127.0.0.1:56379，开发回环实例无密码 |

**空数据库的预置管理员：`admin` / `Admin@2026Dev`，首次登录必须改密。仅限开发环境。**

本次验收脚本已将本机管理员密码改为 **`Admin@2026Verified`**，所以当前已运行实例请用这个密码登录。重新创建空数据库时仍使用初始密码。验收产生的测试部门、账号、审批和打卡保留供核查，不影响新建业务；它们以“验收”或“浏览器验收”命名。

## 方式二：Docker Compose + HTTPS

需要 Docker Engine 及 Compose v2。若机器尚未安装，可按 Docker 官方对应发行版安装说明安装；本仓库附带的本机脚本不改系统目录，不安装 Docker 守护进程。本次机器无 Docker，容器启动未实际执行；已用本机生产 profile + 真正 Nginx HTTPS 验证同一份反代配置，见验收记录。

```bash
cd /workspace/oa-system
bash scripts/prepare-compose.sh
# 查看并记录 .env 中自动生成的 BOOTSTRAP_PASSWORD；不要提交 .env
# 本机生成的自签名证书只用于 https://localhost 验证，浏览器会提示证书不受信任
# 或：cp .env.example .env 后自行填写三个独立强密码与 HTTPS 域名

docker compose config --quiet
docker compose up -d --build
docker compose logs -f backend
```

访问 `https://localhost`，空数据库账号为 `admin`，初始密码取 `.env` 的 `BOOTSTRAP_PASSWORD`，首次必须修改。生产 profile 不使用源码中的开发默认管理员密码。

公网部署时：将 `.env` 的 `CORS_ORIGINS` 改成实际的 `https://oa.公司域名`；将正规 TLS 证书、私钥分别放到 `.runtime/certs/fullchain.pem`、`.runtime/certs/privkey.pem`，配置证书续期；可把 Nginx `server_name _` 改为实际域名。Compose **只映射 443**，后端、数据库、Redis 不映射宿主机端口；防火墙仅开放 443。不要把 Vite 或 `dev` profile 暴露公网。

Nginx 固定内网地址 `172.30.0.10`，后端仅信任该来源的 `X-OA-Client-IP`，Nginx 会覆盖外部同名头。若内网段冲突，请同步修改 Compose 子网、Nginx 固定地址和 `TRUSTED_PROXIES`。数据库和 Redis 分别用 `.env` 中的密码，证明文件存在 `uploads` 卷；持久化卷包括 `postgres-data`、`redis-data`、`uploads`。`docker compose down` 保留卷；日常停止不要使用 `down -v`。

建议备份 PostgreSQL 与上传文件卷，保留 `.env` 和 TLS 私钥的安全副本；修改 `.env` 中数据库密码不会自动更改已有数据库的用户密码。

## 手工验证操作

1. 登录管理员，首次改密并重新登录。在“部门组织”建立部门，在“账号与角色”开通负责人（部门负责人角色）、主管（直属上级角色）、员工；编辑部门选择负责人，编辑员工选择主部门和主管。每人一个主部门，审批直接读取组织关系。上级/负责人均未指定或指向自己时拒绝提交，不会自动批准。
2. 在“公司网络”登记实际 SSID 或办公出口 IP。在“假期余额”给员工录入当年年假/调休**当前剩余天数**；“假期配置”调整事假/病假年度上限、法定假可休天数。“审批分流”默认请假、出差/外出 1 天，报销 1000 元，可直接修改。
3. 在“审批单据”管理员代员工提交请假。半天选择 09:00–13:00 或 13:00–18:00；一天为 09:00–18:00。超过阈值需要两级；主管已是部门负责人或未设部门负责人则一次。管理员可在详情中处理当前步骤（禁止自批）；员工和主管使用 API 验证各自权限，详见 [API 文档](docs/api.md)。病假建议附证明，预置法定假必须上传 PDF/PNG/JPEG。
4. 通过后查看余额扣减；尚未开始可撤销并返还，已批人收到站内通知；驳回必须写意见；待批可撤回。事假、病假只核年度上限，不扣手工余额。
5. 提交并批准覆盖当前时刻的出差/外出。在开发“模拟打卡”页选择员工，填写类型、定位、精度、SSID、出口 IP：正常打卡要求登记网络，出勤要求处于批准时段。缺定位、无有效批准或非公司网络均应拒绝。出差/外出每天仍需打出勤卡，无自动生成记录。
6. “打卡记录”“审批单据”按员工、类型、状态/日期筛选和翻页，导出 CSV；“操作审计”核查管理操作。停用账号后新登录与已有会话均不可继续，历史记录仍可由管理员查询。

**时间口径：**统一 `Asia/Shanghai`；申请按自然日计天，含周末和节假日，上午下午各半天，请假、出差和外出跨年需拆单，加班计入开始年度。出差/外出也使用半天边界，跨日申请会覆盖中间夜间；打卡有效期为 `[开始时间,结束时间)`。本期没有节假日工作日历。法定假预置天数为演示配置，需管理员按公司所在地和内部规则调整。

## 报销演示

管理员在“审批单据 → 提交申请”选择员工与“报销”，填写总额、至少一行用途/类别及金额，逐行合计与总额一致，上传至少一张票据（支持多选及移除）。提交后通过“查看 / 审批”核对全部明细、下载票据并处理审批。金额超过配置阈值时须等财务二级批准。

最终批准后支付状态为“待支付”。财务或管理员可在详情中点击“标记已支付”；若登记错误，填写更正原因后“改回待支付”。详情显示操作人、时间、原因和全部支付历史，“操作审计”可核对状态变更。支付登记只记录线下付款结果，不会实际转账。财务登录后有审批单据及消息中心入口，可以处理无需财务二级审批的已批准低额报销。

## 安全与实现说明

- 密码 BCrypt 12 轮，不返回/导出密码哈希；最多 72 UTF-8 字节。连续 5 次登录失败后锁定该登录标识 15 分钟，另设连接来源 IP 尝试上限。
- Redis 保存随机 Bearer 会话；服务端每次请求读取账号启用状态、角色及会话版本。密码重置、改密、账号变更使旧会话失效。前端仅在当前浏览器会话中存令牌，不使用长期 localStorage。
- 管理接口按管理员鉴权；普通用户仅看本人打卡/余额，审批单按申请人、实际审批链或抄送名单授权；财务可查询全部已批准报销并登记支付。附件继承关联单据访问范围。审批检查当前步骤，禁止跳批和自批。
- 管理操作、代提交、审批、模拟打卡、登录/改密/退出和 CSV 导出写数据库审计日志，不记密码或令牌。审批/撤销和余额更新在同一事务，相关用户/单据行锁防止超扣与重复处理。
- CORS 仅允许明确配置的本机/HTTPS 来源，无通配；正式接口忽略客户端自行填写的出口 IP。文件按 UUID 命名且只能鉴权下载，禁止静态公开上传目录。
- SSID/经纬度在 API 中是设备声明，服务端只能校验格式、网络登记和授权时段，无法证明定位未被伪造；若需可靠内网校验，请只登记公司出口 IP。后续正式 App 再加入可信的网络、定位采集和设备控制。

## 已知限制与后续

员工网页与 Flutter App 已提供员工自助申请及审批；当前管理后台的代提交与模拟页用于管理/开发；财务账号可登录后台查看已批准报销、下载票据并登记支付状态。通知仅站内查询，无短信、邮件或推送；无审批转办界面，负责人离职前需先处理/撤回在途单据并调整组织关系。账号停用保留数据，不提供硬删除账号或已关联部门。

余额由管理员录入当前剩余值，并保留本期开始后的余额变动流水；尚未实现年假结转规则；自然日半天模型尚未覆盖各地工作日历、弹性时段和复杂法定假规则。附件只做类型/大小限制，暂不做病毒扫描或未关联附件自动清理。列表默认 200 条分页，审计/通知分别取最新 500/200 条；导出上限 10000 条。当前未实现组织/账号的批量导入、消息推送或第三方集成。

报销费用明细最多 100 行，票据最多 30 张，单张最多 10MB；金额最多两位小数且明细合计必须等于总额。票据仅做文件校验，不验证税票真实性，不做跨单据查重。支付为人工记账，无银行或支付渠道集成。历史报销按 V2 迁移保留，缺失票据不补造；历史已批准单据初始化为待支付，需财务人工核对。新提交报销必须有明细及票据，已提交单据暂不支持编辑。详见 [报销 API](docs/api.md#报销明细票据与支付登记)。

## 公告与消息中心演示

管理员进入“公告管理 → 发布公告”，填写标题和正文，选择全员或某部门（包含下级），可上传最多 30 份 PDF/PNG/JPEG，每份最多 10MB。发布时只保存启用员工，姓名、工号及部门一并快照；入职、离职、调部门不会改变该公告的接收人名单。管理员可查看已读/未读人数及名单、撤回公告，发布和撤回均写入审计。打开详情自动记首次已读时间；管理员本人也是接收人时，查看详情同样计已读。撤回后普通接收人不能再查看正文或下载该公告附件，管理员仍可核对历史回执。

所有角色登录后都有“消息中心”：待我审批、我发起的、抄送我的、系统通知（原站内通知）、公告。顶部显示当前待办及未读通知/公告数量，点击刷新更新；每类每页最多 200 条。公告可打开、标记已读及鉴权下载附件。系统通知保留原接口，统一在消息中心操作，避免两个入口状态不一致。

管理员代提交六类申请时，可在“抄送同事（可多选）”选择最多 100 名启用同事；员工通过 API 传 `ccUserIds`。抄送名单去重且不能包含申请人；提交和最终通过/驳回均发站内通知，详情返回名单。抄送仅赋予单据及附件阅读权限，审批、撤回、支付仍各自校验原权限；若同事本就有审批或财务角色，其原有授权保持。

使用 Flyway V3 增量建表，旧申请默认无抄送，旧通知保持可用。未接入 APNs、FCM、安卓厂商、短信或邮件，也没有伪造推送发送记录；无需证书，站内消息完整可用。没有定时发布、评论、公告审批或客户端后台推送；正文为纯文本，已读回执仅证明打开或标记操作。测试证据保存于 `.runtime/announcement-verification.json`、`.runtime/announce-admin.png` 和 `.runtime/messages-*.png`，均不提交。


## 一期 Flutter 员工 App

详见 [员工端运行与安装说明](mobile/README.md)。已实现首次强制改密、地址配置、工作台汇总、定位打卡、六类申请/审批及抄送、报销明细/多票据、五类消息与公告回执/附件、组织通讯录、资料/余额/工作电话及登录设备管理。

管理员可在「账号与角色」维护职务和工作电话，并查看/退出员工登录设备。通讯录只下发工作电话，不公开登录用个人手机号。Flyway V4 增量添加字段和设备会话表，数据库保存 token 的 SHA-256 标识，Redis 继续维护8小时会话；改密和管理员编辑账号保持原有全部旧会话失效规则。升级前仅在 Redis 的旧会话因缺少设备登记须重新登录，历史业务数据保留。

已实际构建调试包：`.runtime/oa-employee-debug.apk`，不提交 git。仓库根目录执行 `/home/box/Android/platform-tools/adb install -r .runtime/oa-employee-debug.apk` 安装。Linux 未生成 IPA；iOS 后续在 Mac 用同一工程打开 `mobile/ios/Runner.xcworkspace`、配置签名并联调；全员安装仍需适用的苹果企业账号或 MDM 条件。本次没有办理账号、修改服务器/域名/证书或接入真实推送。尚无连接设备的真机定位、Wi-Fi 和系统文件交互实测，具体边界见员工端说明。


## 二期员工办公网页

员工入口：开发时访问 **http://127.0.0.1:5173/staff/**；沿用 HTTPS 反代时访问 **https://localhost/staff/**（本机生产验收端口为8443）。管理后台仍为 `/`，两入口独立构建到同一 `admin/dist`，复用现有 Vite `/api` 开发代理及 Nginx HTTPS 静态资源配置，无需新服务器、证书或后端接口。

使用管理员已开通的员工工号或登录手机号与密码，无新增演示账号。首次必须改密并重新登录；会话沿用后端固定8小时，不自动续期。员工令牌仅放浏览器 `sessionStorage` 的 `oa-staff-token`，与后台 `oa-token` 分开；个人中心可退出单台、其他设备或当前设备，账号停用、改密及会话过期仍由服务端拦截。

- 「提交申请」支持请假、出差、外出、报销、加班、补卡，含抄送、证明、报销最多100行明细及30张票据。提交成功即打开详情。
- 「消息中心」沿用待我审批、我发起的、抄送我的、系统通知、公告分类。可查看详情、当前步骤审批、按规则撤回或撤销、鉴权下载附件；公告打开或标记已读即回执。员工入口不提供财务支付登记，仍在管理后台进行。
- 「通讯录」按部门树（含下级）、姓名/工号/部门搜索，仅展示工作电话；「个人中心」展示资料、假期/调休余额与最新500条流水，支持修改工作电话、密码和管理设备。
- 「打卡记录」支持日期和类型查询、现场/补卡来源及关联单号。**网页不提供现场打卡，请使用手机 App 完成定位与网络校验。**

表单时间均为北京时间，半天模型、跨年、互斥、证明、审批分流、补卡期限和调休退回沿用服务端规则；页面读取 `/attendance-policy` 展示实际配置，不在浏览器另算业务额度。列表每页最多200条，消息通过刷新更新，无真实推送。手机浏览器可用，主要面向电脑；附件、日期选择和多选的原生控件样式随浏览器语言及系统变化。日程、会议的新增能力见下节；未加入待办任务、文档资料或工作台汇总。

构建与验收（先启动现有本机服务；只在开发数据库执行）：

```bash
source scripts/env.sh
mvn -f backend/pom.xml -Dmaven.repo.local="$PWD/.tools/m2" test
npm --prefix admin run build
npm --prefix admin run test:e2e
# 现有四组接口回归按顺序执行，避免互相修改审批配置
python3 scripts/verify-phase2-attend.py
python3 scripts/verify-mvp.py
python3 scripts/verify-announcements.py
python3 scripts/verify-mobile.py
# 沿用本机证书及 HTTPS 配置，同时跑员工网页用例
bash scripts/verify-production.sh
```

员工浏览器用例位于 `admin/tests/staff.spec.ts`，通过真实接口建立独立验收账号/部门及单据，覆盖首次改密、手机号登录、六类提交、报销明细/多票据/下载、撤回、员工审批、加班撤销、公告回执、资料/通讯录、设备退出、刷新恢复和390px窄屏。截图为 `.runtime/staff-desktop.png` 与 `.runtime/staff-mobile.png`，不提交。详见 [员工网页验收记录](docs/staff-web-verification.md)。

## 二期日程与会议

- 管理后台「日程与会议」维护会议室（名称、地点、容量、启停），按时间、会议室和组织者查看会议，也可由管理员本人创建、修改和取消。无会议记录可删除，有记录只停用，保留历史。
- Flutter 工作台与员工网页 `/staff/` 新增「日程与会议」入口：按日期范围看我的日程、查看会议室占用、创建/编辑/取消会议、邀请在职同事、接受或请假（可填原因）。系统通知可直接进入会议。会议室可空，只建日程也支持。
- 业务时间统一为北京时间（Asia/Shanghai），开始/结束必填且结束晚于开始；允许过去开始。会议室即时占用，无需审批；同室时段重叠返回409及冲突会议，取消立即释放。事务锁覆盖并发预定，个人冲突和超容量只提示。停用会议室不能新订或改期进入，原会议仍可查看及维护非时段信息。
- 只有组织者或管理员可修改/取消；全体在职员工可见占用摘要，说明与名单仅组织者/参会人/管理员可见，全部回复情况仅组织者/管理员可见。改时间/会议室重置回复并通知，加入/移出和取消也发系统通知。通知沿用原表，新增可空关联字段，旧通知兼容。
- Flyway **V6** 增量迁移，不修改历史账号、审批或打卡数据。每页最多200条；邀请最多200人。没有循环会议、视频会议、外部日历同步或真实推送，未扩展待办任务、文档资料或工作台汇总。
- 接口字段、隐私与错误码详见 [API 文档](docs/api.md)。验收命令：`python3 scripts/verify-phase2-calendar.py`、`npm --prefix admin run build`、`npm --prefix admin run test:e2e`、`cd mobile && flutter analyze && flutter test`；HTTP 验收默认管理员测试密码可用 `OA_ADMIN_PASSWORD` 覆盖。新增浏览器用例覆盖带会议室创建、冲突拒绝、取消重订、通知回复、改期重置及中文后台维护；Flutter 包含交互测试及可选真实接口测试。不生成正式签名包或 IPA。
